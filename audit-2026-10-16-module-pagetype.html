URL、路由与canonical

U-01 · 主机、类目入口与内链：消除错误跳转依赖

做错 5 原发现：U-1、U-2、U-6、U-7、U-8

问题：历史40/40抽样类目跳307追加availability，10-19复核rugs仍如此；存在多跳、/en等非标准地址与footer带参数内链。历史handle还存在副本、下划线等命名线索。

根因分析 · 可确认的机制：无参类目自动变成参数URL后，会命中已确认的参数noindex规则，入口交付发生冲突。URL命名不漂亮本身不是Google处罚理由。

代码或配置原因 · 待验证：默认库存条件可能与路由跳转绑定；绝对URL、footer配置与历史迁移可能分别生成地址。尚不能认定某个middleware是唯一根因。

定位方法：后端追踪真实GET/Location与默认库存查询；前端盘点绝对URL工具和footer href；运营核对旧handle到实体的确切对应。

实施步骤

  1. 正常无参类目直接200，默认库存筛选留在服务端查询，不通过改浏览器URL实现。
  2. 统一可信生产origin与路由注册表；已确认等价的历史别名直接301/308到最终实体，不能把缺失商品全部跳首页。
  3. 清理站内href空白及自动库存参数；旧handle只有确认实体映射后才迁移，同步内链与Sitemap。

U-02 · canonical：全站只维护一份页面身份规则

做错 1 没做 2 原发现：M-C1、M-C2、M-C3

问题：新44个HTTP请求中43个200；41个200未检出源码canonical，另外两个首页响应指向https://garvee.com/en。

根因分析 · 可确认的机制：可确认的是服务端身份标签缺失或目标错误。缺canonical不等于Google绝不会自行选主URL；但当前输出不符合项目规范，也无法与Sitemap稳定核对。

代码或配置原因 · 待验证：路由未接入共用身份生成器、错误origin/locale配置或客户端补标签都可能造成此结果；具体原因待源码与DOM对照。

定位方法：逐路由追踪canonical输入、服务端输出时机及重复标签；将当前请求URL、实体URL、分享URL和重定向目标分别记录。

实施步骤

  1. 路由先解析实体，再由统一buildCanonical输出一个绝对URL；不要直接使用含追踪参数的location.href。

U-03 · 分页、筛选与排序：请求状态必须进入服务端查询

做错 1 原发现：U-3

问题：历史样本的page2/筛选/排序与默认页商品重叠12/12；page=9999返回200，但缺总页数证据，不能确认越界。

根因分析 · 可确认的机制：当不同请求没有恢复对应数据切片，翻页URL就不能可靠指向下一组内容。canonical相同并不是返回同一批商品的理由。

代码或配置原因 · 待验证：可能是服务端未传递page/filter/sort、cursor换算错误，或缓存忽略业务参数；目前不能由重复商品直接确定是哪一种。

实施步骤

ROB-01 · robots：合并参数指令与具体爬虫规则

做错 1 做对 1 原发现：M-R1、U-9

HTTP与异常状态

HTTP-01 · 零结果、越界和接口故障：先判事实，再选HTTP状态

未验证 1 原发现：U-10

问题：极端价格筛选、随机词搜索和超大页码探针返回200，但尚未取得真实零结果或总页数证据；这些状态分支仍未验证。

根因分析 · 可确认的机制：“接口失败”“查询成功但0匹配”“实体暂缺”和“资源不存在”是不同事实。把它们都写成空数组会使HTTP、正文和Schema一起误判。

代码或配置原因 · 待验证：是否存在空数组统一回退、错误吞掉或越界未校验，当前无后端证据。

定位方法：后端提供结果总数、有效性、错误码、实体生命周期和快照时间，分别构造成功0条与API异常用例。

实施步骤

  1. 输出明确的dataFailed/invalid/missingEntity/zeroResults状态，先判HTTP再生成Head与主体Schema。

  // zeroResults must come from a successful, authoritative result snapshot.
  if (status === 200 && (input.invalid ||
      (input.kind === 'collection' && input.hasUserFilters && input.zeroResults))) status = 404;
  if (status !== 200) {
    return { status, canonical: null, hreflang: {}, normalEntitySchema: false,
      robots: status === 404 || status === 410 ? 'noindex,follow' : null };
  }
  const isSearch = input.kind === 'search';
  const isPrivate = Boolean(input.privatePage);
  const noindex = hasQuery || isSearch || isPrivate;
  const query = input.normalizedQuery ?? url.searchParams.get('q') ?? '';
  // canonicalPath is supplied by the validated entity route registry.
  let canonical = input.canonicalPath
    ? new URL(input.canonicalPath, input.origin ?? 'https://www.garvee.com').href : null;
  if (isSearch) {
    canonical = query ? new URL('/search', input.origin ?? 'https://www.garvee.com') : null;
    if (canonical) {
      canonical.searchParams.set('q', query);
      canonical = canonical.href;
    }
  }
  const hreflang = !isSearch && !isPrivate && input.hreflangEligible
    ? (input.verifiedCanonicalAlternates ?? {}) : {};
  return { status, canonical, hreflang,
    robots: `${noindex ? 'noindex' : 'index'},${isPrivate ? 'nofollow' : 'follow'}`,
    normalEntitySchema: !isPrivate && !isSearch,
    // Add this partition to the full market/content/session-aware HTML cache key.
    policyPartition: hasQuery ? 'query-present' : 'query-absent' };
}
